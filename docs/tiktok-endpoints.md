## รูปแบบร่วมของกลุ่ม `/api/v*/insights/...`
- `time_descriptor`: `{start:"YYYY-MM-DD", end:"YYYY-MM-DD", timezone_offset:25200, scenario, granularity, with_previous_period}` — **รองรับช่วงวันที่กำหนดเองโดยตรง** (ต่างจาก Shopee)
  - scenario 4 = ช่วงย้อนหลัง (end = วันสุดท้าย+1? — หน้า live ส่ง start 09-07 end 09-14 สำหรับ "7 วันที่ผ่านมา" ถึงเมื่อวาน), scenario 2 = วันนี้ (start=today, end=today+1 หรือ "YYYY-MM-DDTHH:00:00"), scenario 1 = promotion
  - granularity: `"ALL"` รวมทั้งช่วง · `"1D"` รายวัน · `"1H"` รายชั่วโมง · `"7D"`/`"30D"` = รวม 1 ค่า (ใช้กับ with_previous_period:true → ได้ timed_stats 2 ค่า คือช่วงก่อนหน้า+ช่วงที่เลือก)
  - `with_previous_period:true` → timed_stats[0] = ช่วงก่อนหน้า, [1] = ช่วงที่เลือก
- `time_selector` (บาง endpoint): `{period:31, granularity:30, base_timestamp:<unix>}` = 7 วันล่าสุด; `{period:10, granularity:1}` = วันนี้ real-time
- เงินเป็น object `{amount:"123.45", amount_formatted:"฿123.45", currency_code:"THB"}` (หน่วยบาทตรง ๆ) · อัตราเป็น string "0.0397"
- `stats_types` = รหัส metric (ตอบกลับเป็น field ชื่อจริง เช่น revenue, orders_cnt)
- วันที่มีข้อมูล offline ล่าสุด: `POST /api/v2/insights/seller/shop/data/available/date` body `{request:{module_names:["US_SellerPC_Overview_MergeId_Offline_Part"],timezone_offset:25200}}` → available_date (เช่น 2026-09-13 = T-2); วันนี้: `POST .../shop/us/overview/today/data/available` body `{request:{today:"2026-09-15"}}` → has_data, available_hour
